# Сценарий демонстрации (7 минут) и структура питча

**Подготовка:** `docker compose up --build` (или `python manage.py migrate && python manage.py seed --reset && python manage.py runserver`), сайт — http://localhost:8000.
Два окна браузера (второе — приватное). Аккаунты: `aida`, `bakyt`, `nurlan` / `pass12345`; модератор `moder` / `moder12345`; администратор `admin` / `admin12345`.

| Время | Что показываем | Что говорим |
|---|---|---|
| 0:00 | Гость: лендинг, цифры, каталог; переключить тёмную тему | «Общая библиотека вашего сообщества: книги есть у людей, но их не найти и не вернуть» |
| 0:45 | Войти как **aida**: колокольчик и красное предупреждение о просрочке с телефоном владельца; «Обмены → На руках» | «Система сама следит за сроками и предупреждает обе стороны — на сайте и по email» |
| 1:45 | В окне 2 как **nurlan**: книга → «Запросить» (дата, телефон). В окне 1 у владельца — уведомление; принять → передать → вернуть | «Номер телефона видит только вторая сторона обмена; статусы защищены от гонок» |
| 3:00 | **nurlan**: «Предложить книгу»; **moder**: «Модерация» → одобрить одну, отклонить другую с причиной; автор видит уведомление | «Каталог растёт силами участников, но качество под контролем» |

| 4:45 | «Встречи» и «Моё чтение»: цель на год, рекомендации по жанрам | «Клуб живёт не только обменом» |
| 5:30 | **admin**: «Аналитика» (участники, обмены, просрочки, графики по неделям); удалить чужой отзыв | «Модератор скрывает, администратор удаляет» |
| 6:00 | Профиль: «Скачать мои данные», «Удалить аккаунт». Затем `/api/docs/` | «Приватность и открытый API — из коробки» |
| 6:30 | Слайд архитектуры: 12 приложений, `docker compose up --scale web=3`, замеры из [SCALING.md](SCALING.md) | «Готово к росту: от одного сервера к тысячам участников» |

**Запасные приёмы:** показать письмо в логах (`docker compose logs -f worker`), раздел «Правки» (было → стало), сброс пароля кодом из терминала.

## Структура питча (10 слайдов)
1. **Проблема:** книги простаивают, обмен хаотичный, возвраты теряются.
2. **Решение:** закрытая библиотека сообщества (скриншот лендинга).
3. **Как это работает:** запрос → договорённость → передача → напоминания → возврат.
4. **Продукт:** модерация, встречи, цели, рекомендации, уведомления (3–4 скриншота).
5. **Почему мы:** сравнение по классам решений ([PRODUCT.md](PRODUCT.md) §1).
6. **Рынок и сегменты:** университеты, IT-компании, клубы, сообщества.
7. **Модель дохода:** тарифы (гипотезы) и пилотное предложение.
8. **Готовность и технологии:** что сделано, тесты, масштабирование, безопасность.
9. **План:** мультитенантность, биллинг, локализация, мобильный клиент ([PRODUCT.md](PRODUCT.md) §4).
10. **Запрос:** пилот на 6–8 недель, критерии успеха.

*Цифры рынка и цены в слайдах подтвердите собственным исследованием: в документах они помечены как гипотезы.*
